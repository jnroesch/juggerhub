# Contract: Email Templates & Rendering

**Feature**: 039-transactional-email-templates | **Date**: 2026-08-01

Defines the variable contract for the four new templates, the escaping rule every template
now inherits, and the localizer keys backing them.

---

## EC-1. Escaping contract (applies to every template, new and existing)

`EmailTemplateService.ReplaceVariables` substitutes values **HTML-encoded by default**. A
value is emitted raw only when the caller wraps it explicitly.

```
RawHtml(string Value)     — marker for values that are intentionally markup
```

| Rule | Statement |
|---|---|
| EC-1.1 | Every value in the variables dictionary is HTML-encoded before substitution, unless it is a `RawHtml`. |
| EC-1.2 | `RawHtml` must be applied at the point the value is supplied — never inferred from the variable name or template. |
| EC-1.3 | URLs are **not** wrapped. Encoding is correct inside `href` (`&` → `&amp;` is required there). |
| EC-1.4 | Only two existing variables qualify for `RawHtml`: `PLAN_FEATURES` and `STATUS_STYLE`, both in unused boilerplate generators (research D1). |
| EC-1.5 | **Subjects are outside this contract.** They are composed by the calling service and never pass through `ReplaceVariables`. Encoding them would render entities visibly in the recipient's inbox (FR-010). |

**Conditional blocks** (`{{#if X}}…{{/if}}`) are unaffected — they are driven by `bool`
values, which have no markup to encode.

## EC-2. Shared variables (supplied by `AddSharedUrls`, available to every template)

| Variable | Source | Status |
|---|---|---|
| `DASHBOARD_URL` | `EmailOptions.FrontendBaseUrl` | Existing |
| `SETTINGS_URL` | `{base}/settings/notifications` | Existing |
| **`PRIVACY_URL`** | `{base}/privacy` | **New** |
| **`IMPRINT_URL`** | `{base}/imprint` | **New** |

All are derived from the single configured frontend base URL, so no email can link to a
different host than the link beside it (FR-023). `TryAdd` semantics are preserved: a caller
may override, but none does.

`EMAIL_TITLE` and `FOOTER_REASON` are supplied per-template by each generator.

## EC-3. `event-cancelled.html`

Generated by `GenerateEventCancelledEmailAsync(eventName, eventUrl, culture)`.

| Variable | Type | Content |
|---|---|---|
| `EMAIL_TITLE` | localized | `title.eventCancelled` |
| `EVENT_NAME` | user-supplied | Encoded per EC-1 |
| `EVENT_URL` | URL | `{base}/events/{eventId}` |
| `FOOTER_REASON` | localized | `footer.eventCancelled` |

Body must convey: the event is cancelled by its organiser; no further sign-ups or
waiting-list joins are accepted; the event page remains viewable. Call-to-action links to
`EVENT_URL`, with the `.alt-link` plain-URL fallback.

## EC-7. Styling contract

All four use only classes already defined in `base-styles.html` — `.content`, `.eyebrow`,
`h1`, `.content p`, `.button`, `.alt-link`, and (party news only) the inline excerpt-card
markup copied from `team-news.html`. **No new CSS rule may be added** to `base-styles.html`
(FR-004).

Each body is a single `<div class="content">…</div>`, matching every existing template, since
the header and footer are concatenated around it by `GenerateEmailAsync`.

## EC-8. Localizer contract

`IEmailLocalizer` gains a formatting overload:

```
string Get(string key, string culture, params object[] args)
```

`string.Format` is applied to the resolved value with the invariant culture. Placeholders are
positional (`{0}`, `{1}`) because word order differs across en/de/es.

### New keys — all three languages required

| Key | Args | Used for |
|---|---|---|
| `subject.eventCancelled` | `{0}` event | Subject |
| `subject.partyRequest` | `{0}` event, `{1}` team | Subject |
| `subject.partyNews` | `{0}` team, `{1}` event | Subject |
| `subject.marketInvite` | `{0}` team, `{1}` event | Subject |
| `title.eventCancelled` | — | `EMAIL_TITLE` |
| `title.partyRequest` | — | `EMAIL_TITLE` |
| `title.partyNews` | — | `EMAIL_TITLE` |
| `title.marketInvite` | — | `EMAIL_TITLE` |
| `footer.eventCancelled` | — | `FOOTER_REASON` |
| `footer.partyRequest` | — | `FOOTER_REASON` |
| `footer.partyNews` | — | `FOOTER_REASON` |
| `footer.marketInvite` | — | `FOOTER_REASON` |

`Get` already falls back to English for a missing culture and returns the key itself for a
missing key — so a typo surfaces as a visible key string rather than an exception.

## EC-9. Template parity contract (FR-026a)

For each of the four templates, the `en`, `de`, and `es` variants MUST contain an identical
set of `{{PLACEHOLDER}}` tokens.

`LoadTemplateAsync` falls back per **file**. A `de` template missing `{{PARTY_URL}}` therefore
produces a German email with no call-to-action, no exception, and no log line. A test extracts
placeholders from all three variants of each template and asserts set equality.

---

## EC-10. Footer contract

`footer.html` in all three languages gains privacy and imprint links in the existing
`.footer-links` column, alongside "Manage notifications" and "Contact us", using `PRIVACY_URL`
and `IMPRINT_URL`. Link text is localized per file; the existing `.footer-links a` styling is
reused with no new CSS.
